# 性能优化记录

2026-09-20，本机 Windows / SQLite 合成基准。保留现有调度规则和 SQLite，未引入 MySQL 或缓存服务。

## 同条件对比

运行 `python -B -X utf8 tests/performance.py`。使用独立临时库、32 个暂停任务，每个任务 200 条事件、8 KiB 响应摘要、约 50 KB 请求体。每项运行 3 组，每组 20 次，取单次平均耗时的中位数。无模型调用和通知发送。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 单任务保存 | 9.353 ms | 3.610 ms |
| 列表快照与 JSON 编码 | 21.863 ms | 0.160 ms |
| 一次普通列表 JSON | 1,660,086 bytes | 26,326 bytes |
| 初始化一个请求 Lane | 20.017 ms | 0.002 ms |
| 终端记录处理 | 0.176 ms | 小于 0.001 ms |
| 60 次终端记录处理的净分配 | 643,956 bytes | 72 bytes |

单任务保存耗时下降约 **61%**，普通列表数据量下降约 **98.4%**。Python 列表保持 1.5 秒刷新周期，只有打开的详情任务携带历史及摘要。

优化前脚本结束时 SQLite 文件仍被连接占用；优化后可正常关闭并清理临时数据库。耗时会随磁盘、系统负载和 Windows DPAPI 开销变化，上表不代表服务器的固定吞吐能力。

## 实施内容

- **SQLite**：Python 复用一条受现有调度锁保护的连接，启用 WAL；关键状态仍事务提交，退出显式关闭连接。表结构不变，保存与恢复继续使用原有任务快照。
- **TLS**：所有 Lane 共用只读 TLS 上下文，证书加载在进程启动时完成。连接、socket、取消状态仍逐 Lane 独立；实际 TLS 握手仍正常执行。
- **历史**：网页适配层不再生成未使用的终端记录。网页事件与摘要仍保留，根目录终端程序行为保持原状。
- **状态同步**：普通列表只复制概要；`?detail=<任务ID>` 为打开的任务读取事件与摘要。
- **浏览器刷新**：普通 SSE 更新以 250 ms 合并保存与通知 UI；成功、结束、暂停、取消即时更新，`pagehide` 和销毁刷新待写状态。
- **任务中心**：保留现有列表和未变化的任务卡片，仅替换变化卡片；焦点、勾选与倒计时保持有效。抽屉继续按字段更新。
- **通知队列**：内存只保留 queued / retrying，已完成回执按 SQLite 主键查询；最多同时投递 4 条，终态释放内存中的记录与凭据。

## 验证与边界

`npm run check` 检查类型；`npm test` 覆盖双端并行、首次成功、保活恢复、代理、暂停取消、SQLite 重启恢复、通知重试、远程认证和流式写入合并。浏览器实测检查未变化卡片复用、焦点与选择保持、列表增删、Python 详情按需加载及 Server 酱表单。

当前 Python 上限为 8 个并行轮次，单轮探活最多 16 个 HTTP 请求；持续保活每任务每轮只请求一次。实际可承载任务数还受连接耗时、上游限流和服务器资源影响。尚未做真实模型吞吐、Docker CPU/内存或目标服务器容量压测。

浏览器任务仍依赖页面和 localStorage，受浏览器存储配额及后台页面节流影响；长期无人值守任务使用 Python 调度。SQLite 由单实例持有，部署方式见 [Docker / 1Panel](../DEPLOY.md)。
